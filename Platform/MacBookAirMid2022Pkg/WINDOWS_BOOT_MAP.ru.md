# Карта: Windows 11 ARM на MacBook Air M2 (J413, T8112)

> Всё ниже получено чтением кода и сборкой. **На железе не запускалось ничего.** Номера прерываний и адреса взяты из
> дерева устройств Asahi Linux (`t8112.dtsi`), а не из ADT вашей машины.

## Главный вывод

Чтобы Windows **загрузилась**, своих Windows-драйверов почти не нужно. Нужны три вещи ниже уровня Windows:
гипервизор, который изображает стандартное железо (GICv3, PSCI, PL011), прошивка с правильными ACPI-таблицами,
и USB-контроллер, оставленный прошивкой в рабочем состоянии. Родные драйверы нужны уже после загрузки: клавиатура,
трекпад, NVMe, питание.

Два драйвера, о которых обычно думают первыми, написать **нельзя**:
- **Контроллер прерываний (AIC).** Интерфейс HAL Extension для контроллеров прерываний Microsoft убрала ещё до
  Windows 10; в заголовке `nthalext.h` остались только таймеры и DMA, и расширения требуют подписи Microsoft.
  Поэтому единственный путь: виртуальный GICv3 в `m1n1_windows`.
- **IOMMU (DART).** В Windows нет способа описать IOMMU, кроме стандартного ARM SMMU (IORT). DART должен быть
  настроен до Windows: bypass или статическая identity-карта памяти.

## Трудные узлы

**A. Отладчик ядра не видит UART Apple.** В DBG2 стоит подтип 0xA по адресу UART Samsung-типа. Windows KD такой порт не
поддерживает (в списке подтипов DBG2 его нет), поэтому зависание на передаче управления ядру сейчас невидимо.
Решение: гипервизор изображает PL011 (подтип 0x3) или SBSA UART, перехватывает его регистры и пишет в настоящий UART;
в DBG2 указывается он. Заготовка `hv_vuart.c` есть. Без этого узла остальные отлаживаются вслепую.

**B. PSCI.** Неизвестные SMC возвращают номер функции вместо `NOT_SUPPORTED`; `SMCCC_VERSION` отвечает «не
поддерживается», хотя `PSCI_FEATURES` говорит обратное; `CPU_ON` запускает ядро внутри цикла гостевого m1n1 с включённым
MMU, что нарушает спецификацию. Первый запуск стоит делать на одном ядре (`-C 0`).

**C. USB без драйвера DART.** Штатный `USBXHCI` работает с физическими адресами. Варианты: (1) bypass, если его
поддерживают именно эти DART (бит 0 регистра PARAMS2, виден только на железе); (2) identity-карта всей памяти
страницами 16K, которую строит прошивка перед `ExitBootServices`. Кроме того, прошивка должна оставить DWC3 в режиме
хоста с настроенным PHY: m1n1 этого не делает. В исходниках U-Boot и m1n1 найдены ошибки в сбросе TLB для DART t8110,
копировать их нельзя.

**D. Клавиатура и трекпад.** На J413 это не SPI, а сопроцессор MTP через dockchannel. Драйвер: KMDF + Virtual HID
Framework. Нужны RTKit-пробуждение MTP, обмен через FIFO dockchannel, загрузка прошивки мультитача, GPIO через SMC.
DMA сопроцессора идёт через свой DART (тот же вопрос, что в узле C). До готовности: USB-клавиатура.

**E. NVMe.** Контроллер Apple ANS: нестандартный NVMe поверх RTKit и SART. Нужен свой StorPort-минипорт. Для загрузки
с USB не требуется.

**F. Память и адреса прошивки (частично сделано).** Области boot args/ADT, память загрузчика ниже прошивки и фреймбуфер теперь резервируются; куча загрузчика выше прошивки не резервируется, её границу прошивка узнать не может. Исходное состояние:  Прошивка копирует boot args и ADT по фиксированным адресам `0x840000000` и
`0x840004000` и не резервирует их; куча гостевого m1n1 тоже не зарезервирована. UEFI-переменные не сохраняются,
часы и RNG ненастоящие, сброс и выключение просто перезагружают машину.

## Порядок работы

1. Узел A (PL011 в гипервизоре + DBG2): без него нет диагностики.
2. Узел B (PSCI) и резервирование памяти (F).
3. Первый запуск на железе: одно ядро, смотрим лог vGIC и KD.
4. Узел C (DART + режим хоста USB), затем образ Windows на USB.
5. Узел D, затем E.

## Что можно отдать на «рутину»

Каркасы драйверов и сборка (clang-cl + lld-link с заголовками WDK: проверено, пробный KMDF-драйвер собирается и
подписывается на Linux), INF-файлы, перенос таблиц регистров из исходников Asahi, HID-дескрипторы, подготовка образа
Windows. Узлы A, B, C требуют сверки со спецификациями и остаются за основной работой.

## Сборка драйверов

Windows-драйверы собираются на Linux: `clang-cl --target=aarch64-pc-windows-msvc`, `lld-link /driver /kernel
/subsystem:native /entry:FxDriverEntry`, заголовки и библиотеки из NuGet-пакетов WDK. Подпись тестовая
(`osslsigncode`), на машине нужен `bcdedit -set TESTSIGNING ON`. Каталог (`.cat`) на Linux сделать нечем.
